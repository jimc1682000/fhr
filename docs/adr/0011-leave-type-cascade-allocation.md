# 0011. 請假假別依餘額串接分配，整筆不拆單

- Status: Accepted
- Date: 2026-06-03

## Context

送請假單時要選假別。手動選容易用錯順序（例如還有補休卻先用特休），也容易超過 WFH 假別的每月上限。重跑 `portal-apply` 時，已送出的時數還可能被重複計算。

## Decision

- `lib/cascade.py` 依 `type_hint` 對應到串接順序：遲到／早退／整日請假走「補休 → 特休 → 事假」，病假走「有薪病假 → 半薪病假」，WFH 走 WFH 假別。
- 依日期排序，逐筆沿串接往下找，第一個剩餘時數足夠的假別吸收整筆。
- 一筆不拆成兩張單：例如補休只剩 1 小時、該筆需要 2 小時，就整筆落到下一層。
- 有月上限的假別（WFH 假別）以 `(假別, YYYY-MM)` 獨立計算額度；沒有上限的末層（事假、半薪病假）來者不拒。
- `already_applied`（通常是狀態檔的 `applied_forms.leave`）先預扣，只扣有月上限的類別，避免重跑時重複扣或把已核准的假計算兩次。
- 串接順序（`DEFAULT_CASCADES`）與月上限（`MONTHLY_CAPS_HOURS`）是 `lib/cascade.py` 內的常數，`allocate()` 可由呼叫端以 `cascades` 參數覆寫；互動模式下使用者仍可逐筆改假別。

## Consequences

- 餘額來自 Portal 的餘額表格。PR #41 發現解析器假設第 0 列就是表頭，實際表格包在巢狀 table 且含雜訊列，結果全部解析成 `None`，串接把補休與有薪病假當成無上限亂配。現在以第一欄為「加班」的列動態定位表頭，依序讀取可休總時數、已休、剩餘。
- `portal-sync` 翻頁改為 Python 端逐頁短 eval，避免單一長 eval 卡住 `agent-browser` daemon 而逾時。
- 不拆單代表某些情況會用到較後面的假別，即使前一層還剩少量時數。
